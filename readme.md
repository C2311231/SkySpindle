# SkySpindle
#### Video Demo:  https://youtu.be/kn8z4xmTRlk
#### Description:
A stylish web interface for a GRBL CNC machine inspired by Mainsail. SkySpindle is separated into three sections as I found this to be the best way to organize the project. 

##### Web Interface
The first section and what I believe to be the most complex is the Web Interface. The Web Interface contains nine JavaScript files besides the ones downloaded on first run, nine CSS files, and ten HTML files. Additionally, it contains four python files to host and handle requests from the interface. The main reason for the large number of CSS, JS, and HTML files is that the interface is designed to be modular, so the necessary files are added for each section and then adding a single line to the main.html file adds the section to the web interface. This should make expansion easier in the future. The "__init__.py" file simply starts the flask app. "_scheduled.py" and "_Websocketio.py" manage the ongoing functions while the program is running. "_Websocketio.py" is responsible for communication with clients. "_scheduled.py" handles periodic functions. The last file "_commons.py" is just used to prevent looped imports.

##### GRBL TOOLS
This section is responsible for handling the connection and communication with the machine. "__init__.py" defines the GRBLConection class and its many functions. Most of this has to do with sending data to the machine. "_receiveThread.py" and "_transmitThread.py" send and receive data to the machine. Sending the data must be done on its own thread because otherwise the program runs into issues of sending multiple commands at the same time and confuses the machine. This way commands are appended to a list and then sent on one thread. The receiving thread is similar but is responsible for receiving data and finding out what its significance is. "_fileTransmission.py" is another thread that is spawned when an operation is started. It sends commands to the buffer and ensures that the machine buffer does not overflow. The final file "_gcodeParser.py" is no longer in use but is still there in case I manage to make it work as intended. In its current state it is intended to calculate the time it will take to run a GCODE file, however, its estimates are highly inaccurate so it was replaced with a different algorithm that was much simpler, but the operation must run for a while to be accurate. If I get time in the future, I would like to rewrite this entire section because it is not well designed as much of it relies on features in the Web Interface section and cannot be used separately. 

##### Helpers
The helpers section contains functions that I believed at the time would be useful throughout the project or could be in the future, however, most all only used once.

##### Other files
The project contains a few other files that are not very important for using the program. The "version.json" file was intended to allow the user to update through the interface. I did get it to work, however, I hated how I implemented it so that feature was removed for now. The project also contains a "requirements.txt" file to make first setup much easier and "main.py" to start the program. Most of the other files are downloaded automatically on the first run. This includes Ace (for syntax highlighted in browser file editing.), GRBL Settings Codes, and Socket IO (For browser communication). I was going to have these files just grabbed at runtime but due to this program being used on CNC machine which may not have internet access I decided that downloading them was a better solution. The rest of the files are for GitHub. 

#### Basic Usage
Upon first run the program will download some files that may take a while. Afterwards you should be able to access the Web Interface by going to http://ip-of-computer:5000. This will load the Web Interface. In the top left corner of the screen is the connection section. Find the correct serial/USB port in the dropdown then push connect. You should now be able to use the jog controls and send commands. To upload a file, drag and drop onto the page or push the button in the operations section. After the file is uploaded it should appear in the operation section along with a delete button and a load button. After loading the file, you will see it in the file editor and the operations section will change to the live view. You can edit the file and press the save button on the top of the file editor to save the edited version. If you change the file, you must cancel and reload the operation to get the new version. Pressing the start button will start the operation. There are two pause options, one will stop the spindle and one will not. Use the tooltips for help. You can resume with the start button again. Pressing the cancel button will unload the operation. Also, at any time you can press the ESTOP button at the top of the screen to send a reboot command to the machine.
